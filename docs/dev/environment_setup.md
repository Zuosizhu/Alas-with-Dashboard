# Environment Setup — `alas_wrapped`

> **Status**: Verified Feb 2026
> **Scope**: `alas_wrapped` development and execution environment

## Overview

`alas_wrapped/` uses **Python 3.9** with dependencies managed by **[UV](https://docs.astral.sh/uv/)**. The dependency graph is pinned via `uv pip compile` to produce a reproducible lockfile.

## Launch Entry Points

Canonical launcher for this repository:

```batch
start_alas.bat [options] [config_name]
```

Direct wrapped launch (useful for debugging launcher behavior):

```bash
cd alas_wrapped
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe gui.py --run PatrickCustom
```

Compatibility wrappers (`alas_wrapped/alas.bat`, `alas_wrapped/deploy/launcher/Alas.bat`) delegate to `start_alas.bat` and are not separate launcher implementations.

## File Layout

| File | Purpose |
|------|---------|
| `requirements-in.txt` | **Input** — direct dependencies with version pins |
| `overrides.txt` | **Constraint overrides** — tells UV to allow incompatible version combinations that work at runtime (e.g., mxnet + numpy) |
| `requirements.txt` | **Lockfile** — auto-generated by `uv pip compile`, fully pinned transitive deps. Do not edit by hand. |

## Creating the Virtual Environment

```bash
cd alas_wrapped
uv venv --python=3.9 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt --overrides overrides.txt
```

## Updating Dependencies

1. Edit `requirements-in.txt` (add/change/remove a direct dependency)
2. If needed, update `overrides.txt` for resolver compatibility
3. Regenerate the lockfile:

```bash
cd alas_wrapped
uv pip compile requirements-in.txt \
  --python-version=3.9 \
  --overrides=overrides.txt \
  --output-file=requirements.txt \
  --annotation-style=line \
  --only-binary av
```

4. Rebuild the venv (or `uv pip install -r requirements.txt` into the existing one)

## Key Constraints

### Why Python 3.9 (not 3.7/3.8)?

ALAS was originally written for Python 3.7.6, but critical dependencies (`numpy`, `scipy`, `av`) no longer ship pre-built wheels for Python 3.7 or 3.8 on Windows. Python 3.9 is the oldest version with binary wheel availability for all required packages.

### Why `overrides.txt`?

`mxnet==1.6.0` declares `numpy>=1.8.2,<1.17.0`, but no numpy in that range has cp39 Windows wheels. At runtime, mxnet 1.6.0 works fine with numpy 1.19.5. The override tells UV's resolver to accept this.

### Why `av==12.0.0` (not 10.0.0)?

`av==10.0.0` has no prebuilt cp39 Windows wheel and fails to compile from source with modern Cython. `av==12.0.0` is the lowest version with a prebuilt `cp39-win_amd64` wheel.

### Why `--only-binary av`?

Ensures UV never attempts to build `av` from source (which would fail on Windows without FFmpeg headers).

## Verification

A healthy environment must pass these checks:

```bash
# Core imports work
.venv/Scripts/python.exe -c "import module; import cv2; import cnocr; print('OK')"

# PyTorch is NOT installed (would indicate dependency bloat)
.venv/Scripts/python.exe -c "import torch"  # Should raise ImportError

# Package count should be ~90, not 159+
uv pip list --python .venv/Scripts/python.exe
# (count lines manually, or in PowerShell: uv pip list --python .venv/Scripts/python.exe | Measure-Object -Line)
```

## Configuration

After creating the venv, ensure `config/deploy.yaml` points to the correct executables:

```yaml
Python:
  PythonExecutable: ./.venv/Scripts/python.exe
  InstallDependencies: false   # UV manages deps, not ALAS

Git:
  GitExecutable: git
  AutoUpdate: false            # We manage updates via git

Adb:
  AdbExecutable: adb
```
